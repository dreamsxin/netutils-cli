# 端口进程查询与管理 — 需求

**状态：已批准**

## 问题与目标

用户需要从本机网络端口快速找到占用该端口的进程，并在确认后结束指定进程。现有连接列表适合检查 TCP/UDP 连接，但按端口定位进程和管理进程需要更直接、明确的操作入口。

## 需求

### R1 按端口查询进程

用户可以查询本机指定端口的进程占用情况。

**验收标准**

- 支持查询 TCP 和 UDP 本机端口；端口按本地地址匹配，不把远端对端端口误报为本机端口占用。
- 找到匹配项时显示协议、本地地址、PID 和进程名；TCP 结果同时显示连接状态。
- 一个端口由多个进程占用时，结果包含所有可识别的进程，不静默遗漏。
- 未找到占用进程时明确显示无匹配结果，查询本身正常结束。

### R2 进程结束操作

用户可以结束通过查询发现的指定进程。

**验收标准**

- 查询命令默认只读，不会结束或修改任何进程。
- 结束操作要求用户明确指定目标 PID，并在执行前要求确认；非交互运行时必须通过明确的确认选项才能执行。
- 一个端口对应多个 PID 时，不得因端口查询而自动结束全部进程；用户只能明确选择要结束的 PID。
- PID 不存在、权限不足或进程在操作期间已退出时，明确报告失败原因，且不得报告操作成功。
- PID 0 和当前 `netutils` 进程不得作为结束目标。

### R3 平台行为

查询与结束操作在项目支持的 Windows、Linux 和 macOS 平台上提供一致的用户可见行为。

**验收标准**

- 三个平台均可查询 TCP/UDP 本机端口对应的进程信息。
- 平台权限限制导致信息不完整或无法执行结束操作时，结果明确区分“无占用进程”和“无法读取/操作”，并说明权限错误。
- 任一平台均不因缺少可选系统工具而崩溃；无法完成操作时返回明确错误。

### R4 输出与兼容性

命令输出可供终端用户检查，也可供脚本稳定消费。

**验收标准**

- 表格与 JSON 模式都能表达查询结果和操作结果；JSON 包含足以识别端口、协议、PID、进程名及操作成败的信息。
- 无匹配结果、权限错误和结束失败在 JSON 中均可明确区分。
- 现有 `connections` 命令的参数、文本行为和 JSON 字段保持不变。
- 结束操作的确认流程不得在 JSON/非交互模式中挂起等待输入。

### R5 可发现性与语言

用户可以从项目文档发现并正确使用新能力。

**验收标准**

- README 命令索引与示例包含按端口查询以及确认后结束指定进程的用法。
- 新增用户可见文本提供中文和英文版本。
- 命令帮助说明查询的端口含义及结束进程的确认要求。
